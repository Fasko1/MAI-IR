# Ядро индекса и поиска

Реализация самостоятельная. `base.h` содержит динамический массив, хеш-таблицу
с открытой адресацией, heap sort, UTF-8 и файловые функции. `engine.cpp` содержит
внешнюю сортировку, бинарный индекс, рекурсивный разбор выражений, операции над
множествами, VB и TF-IDF. STL встречается только в `query_normalizer.cpp` как
интерфейс существующего токенизатора (`vector<string>`); буфер стеммера,
стоп-список, индекс и поиск используют собственные структуры.

## Сборка

```text
g++ -std=c++17 -O2 -Wall -Wextra -pedantic \
  src/ir/main.cpp src/ir/engine.cpp src/ir/query_normalizer.cpp \
  lab03/funcs/tokenizer.cpp lab04/funcs/stemmer.cpp -o build/ir_engine
```

На Windows добавить `-lshell32` для Unicode command line; MinGW может также
использовать `-static-libgcc -static-libstdc++`. Файлы открываются через UTF-8 →
UTF-16 → `_wfopen`; пути с кириллицей не зависят от системной кодовой страницы.
Для unit executable заменить `src/ir/main.cpp` на `tests_lr7_13/unit.cpp`.

## Команды и результат

```text
ir_engine build --manifest TSV --index FILE [--compressed] [--memory-mb 64]
ir_engine compress --input RAW --output PACKED
ir_engine search --index FILE [--ranked] [--limit 50] [--offset 0] [--query TEXT]
                 [--abbrevs lab03/abbrevs.txt] [--stopwords FILE]
ir_engine stats --index FILE
ir_engine verify --index FILE
ir_engine benchmark --index FILE
```

Манифест UTF-8, необязательный BOM, LF либо CRLF:
`external_id<TAB>stem_file<TAB>title<TAB>url`. Последние две колонки необязательны;
по умолчанию title=id, url пуст. В метаданных табуляции и переводы строк должны
быть заменены пробелом. Пути относительны текущему рабочему каталогу либо абсолютны.
Внешний id — непустая строка, максимум 4096 байтов, уникальная в манифесте.
Каждая непустая строка stem_file — одно вхождение уже нормализованного термина;
UTF-8, без пробелов/NUL, максимум 65536 байтов. Последний LF необязателен.
Пустые файлы разрешены: документ существует в универсуме отрицания.

`build` читает один документ, сортирует его termID и получает tf. Буфер записей
`(termID,docID,tf)` ограничен `memory-mb` (1..4096), серии сортируются собственным
heap sort и сливаются собственной минимальной кучей. Память не зависит линейно
от числа вхождений всего корпуса: словарь + таблица документов + один документ +
буфер серий + одна запись на серию. Контейнеры увеличивают ёмкость геометрически,
поэтому выделенная ёмкость буфера может быть менее чем вдвое больше заданного
полезного объёма. `peak_record_bytes` показывает полезный объём записей.
Серии и временные файлы удаляются при штатном завершении и исключениях; завершение
процесса извне может оставить `*.tmp`/`*.building`. Новый файл публикуется
атомарным rename/MoveFileEx после записи и полной проверки временного файла. Одновременные сборки в один путь не
поддерживаются. Существующий индекс сохраняется при ошибке чтения входа.

Построение и сжатие после записи выполняют `load` и полную `verify`; stdout —
один JSON с размерами, счётчиками и временем. Ошибки файлов/формата — stderr,
ненулевой exit code. `stats`/`verify` возвращают одинаковые полные счётчики;
`verified:true` означает завершение глубокой проверки в этих командах.

Без `--query` поисковик читает stdin по строкам и возвращает JSONL:

```json
{"query":"геном && !вирус","count":123,"total":123,"offset":0,"results":[{"id":"007","title":"Название","url":"https://example.invalid/007","score":0.0}]}
```

`count=total` — все совпадения до пагинации. `limit=0` возвращает только счётчик.
В случае ошибки выражения — `results:[]`, `count:0`, `error:"..."`; следующие
строки продолжают обрабатываться, exit code потока остаётся 0. Пустой запрос —
пустая выдача. Поток вывода состоит только из JSON, диагностика файлов — stderr.
Ключевые слова AND/OR/NOT нечувствительны к ASCII-регистру; `!`, `&&`, `||`,
скобки и неявная конъюнкция поддерживаются. Приоритет NOT > AND > OR.
В ранжированном режиме запрос без явных операторов/скобок — неявное OR.
Лимиты: запрос 65536 байтов, 4096 лексем, 128 вложенных скобок/отрицаний,
2048 уровней дерева выражения. Неизвестный термин означает пустое множество.
Операторы, являющиеся частью идентификатора, не экранируются этим синтаксисом.

Запрос нормализуется `split_into_tokens` → `extract_stem`. По умолчанию
стоп-фильтр выключен; опциональный список сравнивается до стемминга.
Профиль должен совпадать с созданием корпуса. Словарь аббревиатур по умолчанию
`lab03/abbrevs.txt`; для полностью независимого запуска можно указать свой путь
либо пустой аргумент. Индекс не содержит копию профиля лингвистической обработки:
это явное ограничение воспроизводимости, профиль фиксируется сценариями проекта.

## TF-IDF

`idf(t)=ln(1+N/df(t))`; `w(t,d)=(1+ln(tf(t,d)))*idf(t)` при `tf>0`, иначе 0.
Вес запроса — та же формула с частотой в запросе. Норма документа считается
по всему словарю, норма запроса — по известным положительным терминам.
`score=sum(w(t,d)*w(t,q))/(sqrt(sum(w(t,d)^2))*sqrt(sum(w(t,q)^2)))`.
При нулевой норме score=0. Термины под нечётным количеством NOT не участвуют
в весах; двойное отрицание возвращает положительный контекст.
OOV игнорируются в весах, но сохраняют семантику пустого множества в булевой части.
Порядок: score по убыванию, при равенстве внешний id побайтово по возрастанию;
без ранжирования — только внешний id. `double` записан IEEE-754 binary64.
TF-IDF не обучается на тестовой разметке; сглаживание выбрано заранее.

Побайтовый формат индекса и все правила валидации: [FORMAT.md](FORMAT.md).

## API для тестов и обвязки

`Index::load(path)` загружает только словарь/документы; обратные списки читаются
по запросу из файла. `read_postings(termID, Vec<Posting>&)` работает одинаково
для raw/VB. `verify()` проверяет все списки. `vocabulary.find(term,id)` ищет
термин. Объект Index владеет памятью и файловым дескриптором, не копируется.
`build`, `compress`, `search` могут использоваться без CLI из C++.
Все диагностируемые ошибки представлены `ir::Error` с полем message.

`benchmark` группирует списки по df: rare<=2, medium<=100, frequent>100, all.
В `groups` для каждой группы: terms, postings, bytes, seconds, checksum.
Время охватывает seek/read/decode, checksum считается вне замера по декодированным
little-endian парам docID/tf, поэтому совпадает для raw и VB. Загрузка и проверка
checksum файла не входят в время декодирования. Это тёплый файловый benchmark,
результаты зависят от ОС и кеша; сравниваются одинаковые корпуса и повторные прогоны.
## Потоковый вход и постоянный процесс (ноябрь 2026)

`build --inline --manifest data/corpus/stems.tsv --index OUTPUT` читает строки
`id<TAB>term1 term2 ...<TAB>title<TAB>url` в UTF-8. Без `--inline` второй столбец по-прежнему задаёт путь к файлу с одним термином на строку.
Предел строки потокового корпуса — 64 МиБ; пустой список терминов допустим. Индекс в обоих случаях одинаковый бинарный.

`search --protocol --index INDEX --limit 50` сохраняет загруженный индекс в памяти и читает строки
`boolean|ranked<TAB>offset<TAB>query`. Для каждой строки выдаётся один JSON-ответ; синтаксическая ошибка самого запроса
не прерывает следующие запросы. Ошибка транспортного заголовка завершает процесс ненулевым кодом.
Обычный stdin без `--protocol` сохраняет прежний формат «один запрос на строку».
Веб использует один такой процесс с последовательной передачей запросов; параллельные HTTP-запросы защищены блокировкой.
