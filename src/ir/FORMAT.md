# Побайтовый формат MAI IR v1

## Бинарный формат, версия 1

Все целые little-endian, без выравнивания/паддинга. Строка — u32 длина в байтах,
затем ровно столько UTF-8 байтов, без NUL. Неподдержанная версия/флаги отклоняются;
расширяемость достигается явной версией, длиной заголовка и смещениями секций,
а не сериализацией C++ структур с зависимым ABI.

| Смещение | Байты | Поле |
|---:|---:|---|
| 0 | 8 | ASCII `MAIIRIDX` |
| 8 | 4 | version=1 |
| 12 | 4 | flags: 0 raw, 1 VB; остальные значения запрещены |
| 16 | 4 | header_size=96 |
| 20 | 4 | reserved=0 |
| 24 | 8 | document_count |
| 32 | 8 | term_count |
| 40 | 8 | posting_count (сумма df) |
| 48 | 8 | token_count (сумма tf и длин документов) |
| 56 | 8 | document_section_offset=96 |
| 64 | 8 | term_section_offset |
| 72 | 8 | posting_section_offset |
| 80 | 8 | точная длина файла |
| 88 | 8 | FNV-1a64 байтов [96, EOF) |

FNV-1a64: начальное значение 14695981039346656037, для каждого байта xor,
умножение на 1099511628211 по модулю 2^64. Это проверка случайной порчи,
не защита от преднамеренной подмены. Заголовок проверяется структурно;
его поля не входят в checksum.

Прямая таблица содержит `document_count` записей в порядке docID (0..N-1):

| Поле | Формат |
|---|---|
| external_id | строка |
| title | строка |
| url | строка |
| length | u64 число вхождений |
| tfidf_norm | f64, little-endian битовое представление |

Словарь содержит `term_count` записей в порядке назначения termID; порядок
не лексикографический, поиск выполняет собственная хеш-таблица:

| Поле | Формат |
|---|---|
| term | строка |
| df | u32 |
| relative_offset | u64, от posting_section_offset |
| block_bytes | u64 |

Блоки идут подряд в порядке словаря, без дырок. Raw-блок содержит df пар
`docID:u32, tf:u32` (8*df байтов). docID строго возрастают, tf>0.
VB-блок содержит df пар `gap:VB, tf:VB`. Первый gap=docID+1, затем
gap=docID-previousDocID. Все gap положительные. В каждом VB числе группы по
7 бит идут от младшей к старшей; бит 7 равен 1 только в последнем байте.
Например `0 -> 80`, `127 -> ff`, `128 -> 00 81`, `16384 -> 00 00 81`.
Максимум пять байтов для uint32; у пятого payload<=15; избыточная последняя
нулевая группа запрещена. Внешние id не дельта-кодируются: это произвольные строки.

Загрузчик проверяет magic/version/flags, действительный размер файла, порядок
границ, верхние пределы количества записей до выделения памяти, checksum, UTF-8,
уникальность id/терминов, df и размеры/непересечение блоков. `read_postings`
проверяет возрастающие docID, tf, длину и каноничность VB. `verify` декодирует
все блоки и повторно считает длины и нормы каждого документа.

# Дополнения к основному формату

Базовый `index.ir` остаётся совместимым с принятой версией. Новый режим `data/advanced`
строит его по леммам и добавляет отдельные связанные файлы:

- `positions.ir`: словарь поверхностных токенов и упорядоченные координаты (документ, позиция) для строгих цитат.
- `skips.ir`: точки перезапуска декодера сжатых списков, привязанные к контрольной сумме основного индекса.
- `texts.offsets`: смещения исходных статей в `texts.tsv` для сниппетов.
- `index.search.json`: пути для согласованного запуска веб-процесса; публикуется после полного пересчёта.

Все целые поля дополнительных файлов записываются little-endian.

## Координаты — `positions.ir`

Заголовок занимает 40 байт: сигнатура `MAICOOR2` (8), привязка к порядку ID документов (8), число документов (8), число терминов (8), число координат (8). Запись словаря: длина UTF-8 термина (8), сам термин, начальный номер координаты (8), количество координат (8).

Каждая координата занимает 8 байт: старшие 32 бита — внутренний docID, младшие 32 — позиция токена от нуля. Списки отсортированы по документу и позиции. Координаты хранятся без сжатия; Variable Byte применяется к постингам основного индекса.

Для цитаты список k-го слова сдвигается на k позиций и пересекается с остальными. Все исходные токены должны стоять подряд в одном документе. Регистр нормализуется, пунктуация разделяет токены, словоформы внутри кавычек не заменяются леммами. Неизвестное слово обнуляет цитату.

## Прыжки — `skips-*.ir`

Заголовок занимает 40 байт: сигнатура `MAISKIP2`, контрольная сумма основного индекса, его размер, число терминов и шаг — по 8 байт каждое поле. Для каждого термина далее записаны начало и число точек (по 8 байт). Точка занимает 32 байта: docID, предыдущий docID, порядковый номер постинга, байтовое смещение. В конце — контрольная сумма FNV-1a всего предшествующего содержимого (8 байт).

Для списков короче 256 постингов точки не создаются. Шаг 0 означает округлённый вверх корень из DF; фиксированный шаг задаётся `make-skips --step N`. В выбранном наборе используется шаг 32. Файл связан с конкретным основным индексом.

`intersect_skips` ускоряет AND двух терминов. Сжатый блок уже прочитан в буфер; прыжок пропускает декодирование внутри него. `search --no-skips` включает обычное пересечение, `--profile` выводит число сравнений, прыжков и время запроса после загрузки индекса.

## Тексты — `texts.offsets`

Заголовок занимает 32 байта: сигнатура `MAITEXT2`, привязка к ID документов, число документов и размер `texts.tsv` — по 8 байт. Далее для каждого документа записано байтовое смещение его строки (8 байт). Проверка размера и ID предотвращает подключение другого корпуса.

По смещению читается исходная статья для сниппета. Окно ограничено 36 токенами и 280 символами, в вебе — тремя строками. C++ возвращает `snippet_parts` с исходным текстом и признаками совпадения; веб экранирует текст перед добавлением `<mark>`. Сниппет не влияет на отбор или score.

## Настройки запуска — `index.search.json`

JSON содержит пути `lemmas`, `positions`, `texts`, `text-offsets` и `skip-index`. Маркер публикуется после согласованного построения данных; веб выбирает расширенный индекс по его наличию. Словарь лемм — отдельный UTF-8 TSV «словоформа → лемма». Подготовка и команды запуска описаны в [README](../../README.md).
