# ЛР11. Сжатие обратных списков

Из корня: `.\build\ir_engine.exe compress --input data/lab07_index/index.ir --output data/lab11_index/index.ir`.

Сохраняются словарь и прямой индекс. В каждом списке первый docID кодируется
как `docID+1`, остальные как положительные разности. tf кодируется непосредственно.
Variable-byte: группы по 7 бит, младшие группы первыми; старший бит 1 отмечает
последний байт. Это явно описанный вариант VB; это не continuation-bit LEB128.
Например, 128 = `00 81`, 16384 = `00 00 81`.

Декодер отклоняет обрыв, более пяти байтов, uint32 overflow, избыточные нулевые
группы, нулевые разности и выход docID за таблицу. FNV-1a64 контролирует целостность
тела файла. FNV — проверка случайного повреждения, не криптографическая защита.
`verify` дополнительно сверяет все tf, длины и нормы документов.

`.\build\ir_engine.exe benchmark --index data/lab11_index/index.ir` измеряет декодирование групп:
редкие `df<=2`, средние `3<=df<=100`, частые `df>100`, все списки. Время включает
seek/read/decode; хеш вычисляется после замера и совпадает для raw/VB. Для вывода
о скорости нужны повторные прогоны на одной машине. Потерь нет: проверяются
полные списки и равенство поисковых результатов и численных оценок.
